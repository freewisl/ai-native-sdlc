## (B) 거버넌스 판정

원문의 세 문장 중 두 개는 지켜진다. "에이전트는 production 게이트까지만 움직인다" — go 는 `RELEASE_APPROVAL` 을 설정하지 않고(51행), 배포는 `/sdlc:release` 제안으로만 끝내며(35행), 훅 비활성화를 금지한다(51행). "코드를 쓴 에이전트가 그것을 승인할 방법이 없다" — 리뷰어는 별도 컨텍스트의 서브에이전트이고 PR 승인·머지는 코드가 하지 않는다.

문제는 세 번째 문장 "수락된 계획 없이는 구현하지 않는다" 다. `--autopilot` 은 이 '수락' 을 사용자의 최초 한 문장으로 대체하는 **명시적·선택적·solo 한정 편차**이고, 세 곳(스킬 Governance 49-52행, README:117-119, PLAYBOOK-MAPPING:537)에 사유와 범위가 적혀 있다. 편차 자체의 처리는 적절하다. 다만 편차를 지탱해야 할 잔여 통제 세 개가 실제로는 약하다. ① 승인 주체가 기록되지 않는다(F-10) — plan.md 의 `approved_by` 가 비어 있어 감사 시 autopilot 승인과 사람 승인이 같아 보인다. ② 원문이 auto mode 의 전제로 요구한 가드레일 4 + 작업조건 3 을 확인하지 않는다(F-11) — doctor 가 이미 판정 행을 갖고 있는데 쓰지 않는다. ③ "PR 은 브랜치 보호를 통과한다"는 진술이 solo 구성에서 사실이 아니다(F-07) — admin bypass 가 PR 경로에서 ruleset 전체를 우회하므로 `--merge` + bypass 조합에서는 필수 체크 `evals` 가 강제되지 않는다. 여기에 아티팩트 3커밋이 기본 브랜치에 남는 구조(F-08)까지 겹치면 "에이전트가 쓰는 것은 전부 PR 로 온다"는 원칙도 부분적으로만 참이다.

정지조건은 **완전하지 않고 세 문서가 서로 다르다**(F-13): 본문에는 있으나 표에 없는 정지가 둘(비-solo intent 승인, 모순 요구사항), 표에는 solo 조건이 누락, README 는 5개 중 3개만 나열한다. 편차의 opt-in 성격은 지켜진다 — `--merge` 없이 머지하지 않고, 비-solo 는 `--autopilot` 이 있어도 intent·plan 정지를 유지한다. 결론: 편차의 **문서화는 합격**, 편차를 감싸는 **잔여 통제와 기록은 F-07·F-08·F-10·F-11 을 고치기 전까지 불합격**.

## (C) 테스트 없는 새 동작

1. `init.sh` 무플래그 GitHub 자동 감지 — 원격이 github.com 일 때 워크플로가 설치되는지 검증 없음(`tests/scripts.sh` 는 항상 `--github` 를 준다). 재현 쉬움: `git remote add origin https://github.com/x/y.git` 후 무플래그 init.
2. `--no-github` · `--no-solo` — 두 플래그 모두 테스트 0건.
3. solo 자동 감지 전체 경로 — `tests/scripts.sh:7` 이 `SDLC_SKIP_GH_DETECT=1` 을 전역 export 하므로 한 번도 실행되지 않는다. 특히 F-02 의 "조회 실패 시 solo 로 가지 않는다" 는 회귀 테스트가 필요하다(`gh` 를 PATH 앞의 스텁으로 대체하면 네트워크 없이 검증 가능).
4. 보관 토큰 → `--auth oauth` 자동 승격 — `tests/scripts.sh:8` 이 `SDLC_AUTH=api` 로 고정해 미검증. `SDLC_CI_TOKEN_FILE` 을 임시 파일로 주고 워크플로에 `CLAUDE_CODE_OAUTH_TOKEN` 이 렌더되는지 보면 된다.
5. `protect.default_branch` — 설정 키가 동작한다는 사실(프로브로 확인)에 테스트가 없고, init 이 그 값을 채우는지(F-04)도 없다.
6. 푸시 가드 우회·오탐 8종 — `+main`, `refs/heads/main`, `HEAD:refs/heads/main`, `--delete main`, `git -C … push`, 기능 브랜치에서의 `--all`/`--mirror`, `main` 이라는 낱말이 든 부수 명령, 기본 브랜치가 master 인 저장소. 현재 8건은 정상 경로만 덮는다(`tests/hooks.sh:242-260`).
7. `github-setup.sh` 의 dry-run 아닌 경로 전체 — ruleset POST/PUT 멱등성, 코드오너 없는 폴백(134-141행), `--save-token`, `--login`, 조직 소유 저장소. `gh` 를 스텁으로 대체한 계약 테스트(요청 메서드·URL·payload 필드 검증)로 대부분 커버 가능.
8. `/sdlc:go` — `tests/scripts.sh:116` 의 파일 존재 확인 1건뿐. `evals/` 에 트리거 케이스 4종(intent·plan·review·doctor)이 있는데 go 는 없다. go 의 description 이 "알아서 진행해"·"한 바퀴 돌려" 처럼 plan·verify 와 겹칠 수 있으므로 트리거 eval 이 가장 필요한 스킬이다.
9. `roles.autopilot: true` 설정만으로 plan 정지가 사라지는 경로(F-28) — 어떤 형태로도 검증 없음.
10. `<work>.meta/` 분리(0.2.1) — `run-evals.sh --dry-run` 만 테스트되고, 실제 실행에서 기록이 work 밖에 생기는지, 실패 시 `.meta` 가 보존되는지(147행) 미검증.
