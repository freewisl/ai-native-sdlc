AI 주방 한 바퀴

옛날 식당은 요리하는 데 가장 오래 걸렸어요.
이제 로봇 요리사가 요리는 금방 해요.
그래서 나머지 다섯 가지가 중요해졌어요.

주문서 → 레시피 → 요리 → 맛보기 → 서빙 → 손님 반응, 그리고 다시 주문서. 한 줄로 서 있던 일을 빙글빙글 도는 고리로 바꾸는 이야기예요. 각 칸은 종이 한 장(마크다운 파일)으로 끝나고, 다음 칸이 그 종이를 읽어요.

1 · Plan

먹고 싶은 걸 종이에 써요

“왜 배고픈지, 뭘 먹으면 좋을지, 못 먹는 건 뭔지” 로봇이랑 얘기하면서 한 장에 적어요. 그리고 냉장고에 붙여요. 붙인 날짜가 자동으로 남아요.

어른 말로 Claude 와 브레인스토밍해 intent/xxx.md(문제·결과·영향·제약·미해결 질문)를 쓰고 git 에 커밋. 커밋이 곧 감사 추적. 몇 주 → 몇 시간.
2 · Design

레시피를 써요. 규칙 카드가 자동으로 들어가요

주문서를 보고 레시피를 써요. 벽에 걸린 카드북(“땅콩 금지”, “뜨거운 건 뚜껑”)이 알아서 끼어들어요. 어기면 노란 딱지가 붙어요.

어른 말로 승인된 intent 로 spec/xxx.md 생성. .claude/skills/ 의 스킬(보안·규약·UX 정책)이 제약으로 작동하고, 충돌은 “플래그” 로 명시. 스킬은 권고, 강제는 아님.
3 · Build

요리 전에 순서를 먼저 말해요

로봇은 “뭘 먼저 하고 뭘 나중에 할지” 먼저 말하고, 사람이 “좋아” 하면 그때 요리해요. 주방 벽에는 규칙표가 있고, 만지면 안 되는 서랍엔 잠금장치가 있어요. 보조 요리사도 여럿 있어요.

어른 말로 Plan mode(읽기 전용)에서 plan/xxx.md(변경 파일·순서·위험·증명) 승인 후 구현. 규칙표 = CLAUDE.md(명령·규약·구조·“Claude 가 자꾸 틀리는 것”, 같은 실수 2번이면 한 줄 추가). 잠금 = hooks(결정론적 스크립트, 차단/허용). 보조 = 서브에이전트·--worktree 병렬 세션.
4 · Test

내 요리는 내가 먼저 먹어봐요

로봇은 내놓기 전에 꼭 스스로 맛봐요. 맛보기 숟가락은 바꿀 수 없게 잠가 놨어요. 규칙표를 고치면, 예전에 만든 요리 20개를 다시 만들어 보고 여전히 맛있는지 확인해요.

어른 말로 CLAUDE.md 의 Commands 로 검증 명령 명시, 정량 목표(“모든 테스트 통과”, “스크린샷 일치”). 버그 수정 때 테스트 파일 편집 금지 훅. Evals: 최근 작업 20~50건을 “프롬프트+수용 기준” 으로 만들어 CLAUDE.md·스킬·훅이 바뀔 때 CI 에서 재실행. 사고 1건 = eval 1개 추가.
5 · Deploy

서빙 전에 검사원이 세 번 봐요

접시가 나가기 전에 로봇 검사원이 “탔나? 이물질? 주문대로?” 세 번 봐요. 사람은 “진짜 내보낼까” 만 정해요. 홀로 나가는 문은 매니저 열쇠가 있어야 열려요.

어른 말로 REVIEW.md 로 3 패스(bugs·security·compliance), Important 기준·nit 상한 5. 에이전트는 승인 못 함(branch protection). 배포 게이트 훅: prod 배포 명령은 RELEASE_APPROVAL 없으면 exit 2. 환경별 자율도 dev 자유 → staging 제한 → prod 승인. 롤백 명령 1줄 미리 검증.
6 · Maintain

손님 얼굴이 찌푸려지면 종이 울려요

조금 찌푸리면 메모만, 많이 찌푸리면 로봇이 왜인지 살펴보고, 아주 많이 찌푸리면 새 주문서를 써서 맨 앞 냉장고에 붙여요. 그러면 한 바퀴가 다시 돌아요.

어른 말로 결정론적 스크립트가 지표를 감시, 밴드 위반 시 claude -p 호출. 1σ 로그 · 2σ 읽기 전용 진단 · 3σ PR/런북 제안. 진단 결과는 intent.md 형식으로 큐에 들어가 Stage 1 재진입. 정기 코드 스캔(Claude Security), Slack 온콜(Claude Tag)도 여기.
모든 칸에 다 있는 것

안전장치는 네 겹이에요

  1. 규칙표·카드북 — CLAUDE.md, 스킬. “이렇게 해” 라고 말해 주는 것. 권고.
  2. 잠금장치 — hooks. 손을 대면 딸깍 막히는 것. 매번 강제, 로그 남음.
  3. 울타리 — sandbox + permissions. 방 밖(파일·네트워크)으로 못 나감. OS 수준.
  4. 사장님 설정 — managed settings. 요리사가 못 바꾸는 규칙. 규제 기업용.
어느 저장소에서든

내 주방은 어디까지 왔을까

플러그인을 설치한 뒤 저장소에서 /sdlc:doctor 를 실행하면 여섯 칸과 안전장치 네 겹 중 무엇이 있고 무엇이 없는지 ✓ △ ✗ 로 보여 주고, 원문의 채택 순서대로 다음 할 일을 알려 줍니다. 처음 시작은 /sdlc:init 한 번, 그다음은 변경마다 /sdlc:go "요청 한 문장" 한 줄입니다 — 이 여섯 칸을 한 세션에서 이어 돌고, 사람에게는 판단이 필요한 곳에서만 묻습니다.

  1. 냉장고 만들기 — git 저장소이게 없으면 "누가·언제·왜" 가 없어요. 모든 단계의 전제.
  2. 규칙표·종이 3장·잠금장치 — /sdlc:initCLAUDE.md 의 다섯 절, intent/spec/plan 폴더, 훅과 권한이 한 번에 생겨요(있는 파일은 건드리지 않아요). GitHub 주방이면 심부름·열쇠·문 잠금 규칙까지 알아서 붙여요.
  3. 첫 변경 — /sdlc:go "요청 한 문장"주문서 → 레시피 → 순서표 → 요리 → 맛보기 → 검사 → PR 까지 한 번에. 하나씩 하고 싶으면 /sdlc:intent → /sdlc:spec → /sdlc:plan → /sdlc:verify → /sdlc:review.
  4. 다시 만들어보기와 종 — /sdlc:evals, /sdlc:monitor규칙표를 바꿀 때마다 예전 요리를 다시 만들어 보고, 손님 얼굴은 스크립트가 지켜봐요.
