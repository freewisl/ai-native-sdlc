sdlc 플러그인 · 다섯 살 버전

어느 주방에나 들고 가는
도우미 상자

앞에서 본 "AI 주방 한 바퀴"를 진짜로 돌게 만드는 상자예요. 상자를 어떤 주방(코드 저장소)에 가져가서 열면, 규칙표·종이 3장·잠금장치·보조 요리사·종과 저울이 한꺼번에 생겨요.

이미 요리 중인 주방에 가져가도 원래 있던 물건은 하나도 버리지 않아요. 빈 주방에 가져가면 처음부터 다 차려 줘요.

어른 말로 Claude Code 플러그인 sdlc. 설치하면 스킬 19종·훅 7종·에이전트 5종·스크립트·템플릿이 모든 프로젝트에서 쓸 수 있게 되고, 프로젝트별 값은 .sdlc/config.json 하나로 받아요. 쓰는 법은 두 마디 — 저장소마다 /sdlc:init 한 번, 변경마다 /sdlc:go "요청 한 문장".
쓰는 법 · 두 마디

상자를 여는 말 하나, 요리를 시키는 말 하나

그 밑에서 심부름 열여덟 가지와 잠금장치 일곱 개가 알아서 돌아요. 사람이 하는 말은 두 마디예요.

/sdlc:init — 저장소마다 한 번

주방을 둘러보고 알아서 차려요. GitHub 주방인지, 혼자 쓰는 주방인지, 열쇠가 이미 있는지 보고 — 심부름 붙이기, 열쇠 보관, 머지 설정, 문 잠금 규칙까지 해 둔 다음, 바뀐 것은 PR 로 올려요.

GitHub 원격·협업자 수·보관된 구독 토큰 감지 → 워크플로 6종·CODEOWNERS·시크릿·auto-merge·ruleset(요금제가 허용할 때) → doctor → 채택 커밋을 브랜치+PR 로. 사람 몫은 계정당 한 번의 GitHub 로그인 승인과 토큰 발급(브라우저)

/sdlc:go "…" — 변경마다 한 줄

"이거 해줘" 한 마디면 주문서 → 레시피 → 순서표 → 요리 → 맛보기 → 검사 → 서빙 준비(PR)까지 이어서 해요. 정말 물어야 할 때만 멈춰요: 규칙이 서로 부딛힐 때, 세 번 맛봐도 실패할 때, 진짜 홀 문. 팀 주방에서는 서빙(머지) 결정도.

/sdlc:go "요청" · 1인 주방은 기본이 자동 — 순서표 허락 생략 + 체크 초록 뒤 머지(roles.autopilot·roles.auto_merge, init 이 켬). 멈추고 싶으면 그 키를 false 로, 또는 그 한 번만 --no-autopilot / --no-merge. 팀 주방은 주문서·순서표 승인과 머지 결정이 남아요

/sdlc:run — 백로그 끝까지 (선택)

주문서가 쌓여 있으면 상자가 한 장씩 꺼내 요리 → 검사 → PR → 서빙까지 하고, 다 끝나면 자기 요리를 다시 검사해서 고칠 게 있으면 새 주문서를 써요. 고칠 게 없을 때까지요. 혼자 쓰는 주방에서, 주인이 스위치를 켰을 때만.

1인 주방이면 스위치가 켜져 있어요(loop.enabled, 끄려면 false) · 항목마다 새 세션의 go --autopilot --merge · 상한(건수·시간·연속 실패 3회)·slug 별 차단·정지 파일 .sdlc/state/pause · sdlc-autopilot.yml 이 30분마다 1건

나머지 심부름은? go 가 안에서 하나씩 부르는 부품이에요. 승인을 다른 사람이 하는 팀 주방이나 한 번에 담기지 않는 큰 요리에서만 따로 불러요.

한 바퀴 돌 때 상자가 해 주는 일

각 심부름은 /sdlc:이름으로 부르거나, 그냥 말로 부탁해도 알아들어요("인텐트 작성", "리뷰해줘").

★

지름길 · 한 문장으로 한 바퀴

go

"이거 해줘" 한 마디면 주문서 → 레시피 → 순서표 → 요리 → 맛보기 → 검사 → 서빙 준비(PR)까지 상자가 이어서 해요. 정말 물어야 할 때(규칙 충돌, 세 번 맛봐도 실패, 진짜 홀 문 — 팀 주방은 서빙 결정도)만 멈춰요.

/sdlc:go "요청" · 1인 저장소(roles.solo)는 기본이 자동(plan 정지 없음, 체크 초록 뒤 머지) — 승인 의식만 없애고 아티팩트·훅·리뷰·PR 은 그대로. 누가 무엇을 근거로 승인했는지는 approved_by·approval_basis 로 남아요

0

준비 · 상자 열기와 건강검진

init

상자 열기. 주방을 둘러보고(어떤 도구를 쓰는지) 규칙표 빈칸을 채워 줘요.

빌드/테스트 명령 자동 감지, CLAUDE.md 채움, settings 병합, GitHub 원격·1인 저장소·토큰 감지 → github-setup, 채택 PR. 플래그는 감지를 뒤집을 때만(--no-github --solo --auth …)

doctor

건강검진. 뭐가 있고 없는지 ✓△✗ 로 보여 주고, 원문 순서대로 "다음엔 이거" 라고 알려 줘요.

훅 자가시험 6건, config 검사, auto mode 준비도, CI 인증 일관성·시크릿·ruleset·auto-merge, 의존성 그래프 5층 순서

status

종이 3장이 어디까지 갔는지 한 표로.

slug별 intent/spec/plan 상태·날짜·활성 plan·spec 재작업 수

1

주문서 · Plan

intent

"뭐가 불편해? 누가 아파? 어떻게 되면 좋아?" 여섯 개쯤 물어보고 주문서를 써서 냉장고에 붙여요.

intent/<slug>.md(문제·결과·영향·제약·미해결) + git 커밋 = 감사 기록. 승인은 사람이 approve

2

레시피 · Design

spec

승인된 주문서로 레시피를 써요. 벽의 규칙 카드가 자동으로 끼어들고, 어기는 곳엔 노란 딱지를 붙여요.

정책 스킬을 제약으로 호출, Flagged concerns 표 필수, 원문 프롬프트 그대로

policy

"땅콩 금지" 같은 규칙 하나를 카드로 만들어 벽에 붙여요. 붙이면 레시피 쓸 때, 검사할 때 자동으로 읽혀요.

.claude/skills/<name>/SKILL.md 스캐폴드 + config.policies 등록 + 트리거 테스트. 예시 secure-api-review

3

요리 · Build

plan

요리 전에 "어떤 그릇을 만질지, 어떤 순서로, 뭐가 위험한지, 어떻게 맛있다고 증명할지" 순서표를 써서 허락받고 그다음에 요리해요.

플랜 모드 강제 → plan.md 4섹션 → 승인 커밋 → 활성 plan 등록 → 구현. 벗어나면 같은 커밋에 갱신

lesson

같은 실수를 두 번 하면 규칙표에 한 줄 적어요. 그러면 다음부터 안 틀려요.

"Things Claude gets wrong" 한 줄 추가(중복 검사, 한 페이지 초과 경고), 필요 시 eval 연계

4

맛보기 · Test

verify

내 요리는 내가 먼저 먹어봐요. 고장 고칠 땐 먼저 "이거 맛없어" 시험을 만들고, 그 시험은 못 바꾸게 잠근 채로 고쳐요. 마지막엔 다른 요리사가 한 번 더 먹어봐요.

build/test/lint 실행·출력 첨부, --bugfix 실패 테스트 먼저, --ui 스크린샷 루프, 끝에 sdlc-verifier 에이전트

evals

규칙표나 카드를 바꾸면, 예전에 만든 요리 20~50개를 다시 만들어 보고 여전히 맛있는지 확인해요. 사고가 나면 그 요리도 목록에 넣어요.

add 케이스 생성(prompt+fixture+check.sh), run = run-evals.sh(claude -p, 임계치 미달 exit 1 → CI 게이트)

5

서빙 · Deploy

review

검사원이 세 번 봐요: 탔나(버그) · 이물질(보안) · 주문대로인가(레시피·순서표와 비교). 중요한 것과 잔소리를 나누고 잔소리는 5개까지만.

REVIEW.md 3 패스, sdlc-reviewer 에이전트, --pr 로 미해결 코멘트 스윕. 승인은 절대 안 함

release

홀로 나가는 문. 연습 주방은 자유, 예행 주방은 "정말?" 한 번 묻고, 진짜 홀은 매니저 열쇠가 있어야 열려요. 돌아가는 길(롤백)은 미리 연습해 둬요.

dev free / staging ask / production gated(RELEASE_APPROVAL), 롤백 명령 확인, gate.log 기록

6

손님 반응 · Maintain

monitor

종이 손님 얼굴을 지켜봐요. 조금 찌푸리면 메모, 많이 찌푸리면 왜인지 살펴보고, 아주 많이 찌푸리면 새 주문서를 써서 바구니에 넣어요. 종 자체는 계산기라 절대 착각하지 않아요.

monitor.py: 결정론 탐지(Western Electric 규칙) → 1σ log / 2σ 읽기 전용 진단 / 3σ PR·런북·보고서 → intent/triage/

triage

바구니의 주문서를 사람이 하나씩 봐요: 지금 고칠까 · 나중에 · 아냐 괜찮아(이유 적기).

상태 전이 기록·커밋, fix now → plan/spec 인계, dismiss 는 밴드 튜닝 메모

scan

정기적으로 주방 구석구석 상한 것을 찾아요. 작은 건 바로 고치자고 제안하고, 큰 건 주문서로 만들어요.

보안 체크리스트 12항목, 신뢰도·근거 첨부, 주간 워크플로. 호스팅 Claude Security 도입 체크리스트 포함

postmortem

불 났던 이야기를 교훈 노트에 적고, 규칙표에 한 줄, 다시-만들어보기 목록에 한 개, 큰 숙제는 주문서로.

.sdlc/LESSONS.md + lesson + evals add + intent --from-incident (Claude Tag 온콜 패턴의 로컬 버전)

metrics

저울. "주문서 쓰는 데 얼마나 걸렸나, 레시피를 나중에 몇 번 고쳤나, 종이 몇 번 울렸나"를 재요.

스테이지별 선행/후행 지표(git·이벤트·gate.log·히스토리), 없는 데이터는 "source needed"

보조 요리사 5명 · 에이전트

혼자 다 하지 않아요

verifier다 됐다고 하면 새 눈으로 직접 실행해 보고 보고만 해요. 고치지 않아요.
reviewer검사원. 세 번 보고 중요/잔소리 나눠요. 도장은 못 찍어요.
diagnoser종이 울리면 읽기만 하며 "왜?"를 추리해 주문서 초안을 써요.
simplifier요리 끝난 뒤 불필요하게 복잡한 부분을 정리해요. 맛은 그대로.
researcher주방 어디에 뭐가 있는지 찾아와서 짧게 알려 줘요.

어른 말로 각자 컨텍스트 창과 도구 제한이 따로예요(verifier·researcher는 읽기·실행만). 큰 일은 worktree 별로 세션을 2~3개 열어 병렬로 돌리고, 사람은 조율만 해요.

종과 저울 · 자동으로 도는 것

사람이 안 시켜도 도는 것

종 (monitor)30분마다 손님 얼굴(지표)을 재고 30일 평균과 비교해요. 평균에서 얼마나 벗어났는지에 따라 메모 → 진단 → 제안. 탐지에는 AI를 쓰지 않아요. GitHub 심부름 sdlc-monitor.yml이 돌려요.
저울 (metrics)원문이 "이걸 재라"고 한 지표를 스테이지마다 계산해요. 주방에 없는 숫자는 지어내지 않고 "어디서 가져오면 되는지"만 적어요.
심부름 7개 (GitHub Actions)규칙표가 바뀌면 다시-만들어보기, PR마다 검사원, 주문서가 승인되면 레시피 자동 초안, 빌드가 깨지면 3줄 원인 메모, 종 울리기, 주간 상한 것 찾기, 그리고 켰을 때만 30분마다 백로그 한 장을 처리하는 자동 루프. 전부 PR로 도착하고 main엔 직접 못 써요.
사장님 설정 (기업용)규제 회사면 관리자가 "아무도 끌 수 없는" 설정으로 잠금장치·울타리를 고정할 수 있어요. 그 파일과 설치 위치는 상자에 들어 있어요(docs/ENTERPRISE.md).
약속

상자가 절대 안 하는 것

✕
도장 찍기PR 승인은 사람(코드 오너)만. 검사원·심부름 어느 것도 approve 를 안 해요.
✕
혼자 홀에 나가기production 배포는 매니저 열쇠 없이는 불가. 돌아가는 길(롤백)은 늘 허용.
✕
남의 물건 버리기기존 CLAUDE.md·설정·CI·evals 폴더를 덮어쓰거나 지우지 않아요.
✕
종이 착각하기밴드 탐지는 계산기(결정론). AI는 밴드가 깨진 뒤에만, 허락된 만큼만.
